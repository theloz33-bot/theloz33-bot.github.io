개요 & Stage 1–4 파이프라인Overview & the Stage 1–4 pipeline

계약은 네 단계, 게이트도 네 개입니다. 각 단계는 앞 단계의 결과물을 입력으로 받고, 파일에서 실측하기 전에는 다음 단계로 넘어가지 않습니다. The contract is four stages and four gates. Each stage takes the previous output as input, and none of them advances until the file itself has been measured.

STAGE 01

보드Board

  • IN가사 + 레퍼런스 이미지 + 목표 러닝타임lyrics, reference images, target runtime
  • OUT러닝타임에서 정한 컷 수의 보드 · 스타일 바이블 · 키프레임 스틸 · 컷별 프롬프트board (cut count from the runtime), style bible, keyframe stills, per-cut prompts
게이트 — 보드 승인 (또는 사전 승인된 실행)Gate — board approved (or the run is pre-authorized)
STAGE 02

배치Batch

  • IN승인된 보드 + 스틸approved board + stills
  • OUT컷당 클립 1개, 매니페스트에 기록one clip per cut, logged in the manifest
게이트 — 모든 컷 DONE·다운로드 완료, 또는 실제 블로커 보고Gate — every cut DONE and downloaded, or a real blocker reported
STAGE 03

비주얼 마스터Visual master

  • IN다운로드한 원본 클립downloaded clips
  • OUTv1_visual_master.mp4
게이트 — 파일에서 프레임·fps·해상도·무음 실측Gate — frames, fps, resolution and silence verified on the file
STAGE 04

가사 마스터Lyric master

  • INv1 + 가사 시트 + 음원v1 + lyric sheet + track
  • OUTv2_lyric_master.mp4
게이트 — 프레임에서 큐 타이밍·세이프존 확인, 오디오 검증Gate — every cue's timing and safe zone checked on frames
한 번의 실행, 두 개의 마스터. 음원과 가사(파일의 USLT 태그도 포함)가 함께 주어졌다면 3단계에서 멈추지 않습니다. 무음 마스터를 렌더·실측한 직후 같은 실행에서 자막을 굽고 음원을 합쳐 v1과 v2를 동시에 냅니다. 무음만 요청받은 경우에만 v1에서 멈춥니다. One run, two masters. When a track and lyrics arrive together (an audio file with embedded USLT tags counts), the run does not stop at stage 3: right after the silent master is rendered and probed, it burns the subtitles, muxes the track and delivers v1 and v2 together. Only a silent-only request stops at v1.

세 가지가 이 작업 전체를 붙잡고 있습니다Three things hold the whole job together

러닝타임은 척추Runtime is the spine

1단계에서 초 그리고 프레임 수로 고정하고, 편집은 그 숫자에서 흔들리지 않습니다. 30초 · 24fps는 720프레임이며 “대략 30초”는 없습니다. 컷 길이, 크로스페이드, 자막 큐가 모두 그 숫자에 대한 산수입니다. Fix it in stage 1 in seconds and frames; every cut length, crossfade and subtitle cue is arithmetic against that number. 30 s at 24 fps is 720 frames — never “about 30 seconds”.

생성은 이미 지불한 돈A generation is money already spent

생성 태스크 하나는 이미 결제된 주문입니다. 재생성·재제출·구매·취소는 지불하는 사람만 결정할 수 있고, 스킬은 결함을 한 번 보고하고 멈춥니다. Each generation task is an order already paid for. Nothing authorizes a re-roll, resubmit, purchase or cancel — only the person paying can say yes, so the skill reports the fault once and stops.

파일을 실측하기 전엔 끝이 아님Not done until the file is measured

“720 frames, 24/1 fps, 1366×768, no audio, 30.000 s”는 QC 합격입니다. “잘 나왔다”는 합격이 아닙니다. “720 frames, 24/1 fps, 1366×768, no audio, 30.000 s” is a QC pass. “Looks good” is not.

MiniMax H3 · 5모드 가이드MiniMax H3 · the five-mode guide

H3는 자유 산문이 아니라 구조화된 프롬프트로 학습된 모델입니다. 컷 전환·카메라 무브·입 모양·사운드는 그 형식 토큰을 따를 때 확연히 정확해집니다. 그래서 엔진이 H3(또는 H3를 쓰는 플랫폼)라면 1단계에서 쓴 문단을 그대로 보내지 않고, 모드 → 정렬 문장 → 3필드(또는 6섹션) 구조로 다시 씁니다. H3 was trained on a structured prompt format, not on free prose: shot changes, camera moves, dialogue mouth-shape and sound come out markedly more accurate when the format tokens are respected. When the engine is H3 (or a platform fronting it), the paragraph written in stage 1 is re-addressed as mode → alignment line → three fields (or six sections).

요청 필드와 audio_policy 스펙Request fields and the audio_policy spec

해상도·비율·길이는 프롬프트 본문에 쓰지 않습니다. 호출의 자체 필드로 보내고, 프롬프트와 일치시킵니다. 무음 컷은 텍스트만으로 보장되지 않습니다 — 두 사운드 필드를 N/A로 쓰고 오디오 정책 플래그를 함께 보내야 합니다. Aspect ratio, resolution and duration are never written inside the prompt body: they are sent as the call's own fields and made to match the prompt. A silent cut is not guaranteed by text — write both sound fields as N/A and send the audio policy flag.

# request fields — outside the prompt body
aspect_ratio: "16:9"        # or "9:16" — one aspect for the whole film
duration: 5                # engine tier — 5 or 10 (Ludyte, Seedance), 5–15 on H3; the last cut time sits under it
resolution: "768p"         # default; raise only with the owner's approval

# silent cut — both fields plus the policy flag
overall_soundscape: N/A
non_diegetic_music: N/A
audio_policy: "no_audio"
퍼포먼스 컷의 예외. 노래하는 입은 사용자가 명시적으로 요청한 경우에만 만듭니다. 그때도 non_diegetic_music은 N/A이고, 보컬은 설명하지 않고 오디오 레퍼런스로 주입합니다. 완곡(full mix)이 아니라 리드 보컬 스템만 넣어야 합니다. 첫 프레임과 스템을 함께 붙이므로 이 컷의 모드는 Ref2VA(6섹션)이고, I2VA 정렬 문장으로 보내지 않습니다. The performance-cut exception. A singing mouth is made only when the user explicitly asks for it. Even then non_diegetic_music stays N/A and the vocal is not described — it is injected as an audio reference, and that reference must be a clean lead vocal stem, never a full mix. Because the cut attaches a first frame and a stem, its mode is Ref2VA (six sections) — never an I2VA prompt.

faded runtime = Σ cut lengths − (N − 1) × D

Σ cut lengths = T + (N − 1) × D

import sys
frames = [120, 120, 120]          # per-cut frames, in timeline order
fades  = [6, 0]                   # fade frames per join; 0 = a hard cut at that join
fps = 24
if len(fades) != len(frames) - 1:
    sys.exit("one fade value per join")
if max(fades) * 2 >= min(frames):
    sys.exit("fade too long for the shortest cut")
parts = [f"[{i}:v]fps={fps},scale=1366:768,setsar=1,format=yuv420p,"
         f"settb=AVTB,setpts=PTS-STARTPTS[v{i}]" for i in range(len(frames))]
prev, acc, overlap = "[v0]", 0, 0
for k, f in enumerate(fades, start=1):
    acc += frames[k - 1]
    overlap += f
    off = (acc - overlap) / fps
    out = f"[x{k}]"
    if f == 0:
        parts.append(f"{prev}[v{k}]concat=n=2:v=1:a=0{out}")
    else:
        parts.append(f"{prev}[v{k}]xfade=transition=fade:duration={f/fps:.6f}:offset={off:.6f}{out}")
    prev = out
total = sum(frames) - overlap
print(";".join(parts))
print(f"# expected frames: {total}  ({total / fps:.3f}s)", file=sys.stderr)
